# WattWise — Smart Electricity Consumption Analyzer

تطبيق يحلل استهلاك الكهرباء في منزل واحد ويجاوب عن 3 أسئلة:

1. استهلاكي زاد ولا قل عن المعتاد؟
2. إيه أوقات الاستهلاك الأعلى؟
3. استهلاكي في الأيام الجاية هيبقى كام؟

> **تنبيه مهم:** الداتا تاريخية لمنزل واحد، فالمشروع نموذج تحليلي مبني على بيانات هذا المنزل،
> وليس نظامًا يضمن توفير الكهرباء لأي بيت.

## التشغيل

```bash
pip install -r requirements.txt

# 1) حمّلوا الداتا من UCI (Individual Household Electric Power Consumption)
#    وفكوا الضغط، وحطوا الملف هنا:
#    data/household_power_consumption.txt

python train.py          # تشغيل الـ pipeline وطباعة النتائج في الـ terminal
python -m streamlit run app.py     # الداشبورد
```

لو الملف مش موجود، المشروع بيشتغل تلقائيًا على **بيانات تجريبية مصطنعة** (والواجهة بتعرض
تحذير واضح) عشان تقدروا تجربوا الكود قبل تنزيل الداتا. النتائج على الداتا المصطنعة **ليست
نتائج حقيقية** ولا تُستخدم في أي عرض.

أول تشغيل على الداتا الحقيقية (~2 مليون قراءة بالدقيقة) بياخد شوية وقت، وبعدها بيتحفظ كاش في
`data/hourly_cache.csv`. لو غيرتوا الملف الأصلي امسحوا الكاش.

## تحليل بيانات بيتك أنت (رفع ملف CSV)

من الداشبورد اختاروا **Upload my own CSV** من الشريط الجانبي وارفعوا قراءاتكم. النماذج بتتدرّب من جديد
على بياناتكم (مش على بيت UCI).

**شكل الملف:** صف لكل قراءة، فيه عمود تاريخ/وقت وعمود استهلاك **بالكيلوواط ساعة (kWh)** لفترة القراءة
(مش القراءة التراكمية للعداد).

| timestamp | kwh |
|---|---|
| 2025-01-01 00:00 | 0.42 |
| 2025-01-01 01:00 | 0.38 |

- **قراءات ساعية (أو أدق):** كل التابات شغالة. القراءات الأدق من ساعة بتتجمّع (sum) في ساعات.
- **قراءات يومية:** شغالة، لكن تابتي "أوقات الذروة" و"أنماط الأيام" محتاجين بيانات ساعية.
- **الحد الأدنى 120 يوم** (الأفضل 6 شهور فأكتر، وسنة كاملة عشان الموسمية). الفواتير الشهرية مش كفاية.
- الفاصل (`,` أو `;` أو Tab) بيتعرّف تلقائيًا، والفاصلة العشرية `0,42` مقبولة، وعمود الوقت ممكن يكون منفصل.
- لو التواريخ `31/12/2025` سيبوا خيار day-first شغال، والتواريخ `2025-12-31` بتتقرا صح تلقائيًا.
- ملف تجريبي جاهز: `samples/sample_hourly.csv`. **ده بيانات مصطنعة** عشان تجربة الرفع بس.

**مصادر القراءات:** تصدير من تطبيق شركة الكهرباء أو العداد الذكي، أو جهاز قياس بيتركّب عند العداد
(Shelly EM / Sonoff POW / Emporia وغيرها).

    ├── features.py   # الـ lags والمتوسطات المتحركة وتسميات التصنيف

## دورة حياة المشروع (نقط للشرح مع الطلبة)

1. **Dataset:** قراءات كل دقيقة لـ Global_active_power بالـ kW.
2. **Preprocessing:** القيم `?` بتتحول لـ NaN، المتوسط الساعي بالـ kW = kWh في الساعة، الساعات
   الناقصة (أقل من 30 دقيقة سليمة) تتعامل كقيم مفقودة، واليوم الناقص (أقل من 20 ساعة) بيتحذف.
3. **Feature engineering:** استهلاك أمس، من يومين، من أسبوع، متوسط آخر 7 و30 يوم، يوم الأسبوع،
   الشهر. كل خاصية لليوم t بتستخدم الأيام **قبله فقط** (منع تسريب البيانات).
4. **التقسيم:** زمني 80/20 (من غير shuffle لأنها سلسلة زمنية).
5. **التقييم:** مقارنة كل نموذج بخطوط أساس بسيطة ("زي أمس" و"زي نفس اليوم الأسبوع الماضي").

## الخوارزميات

| الخوارزمية | الاستخدام في المشروع |
|---|---|
| Linear Regression | توقع استهلاك اليوم التالي، والتوقع لعدة أيام (recursive) |
| KNN | أقرب أيام مشابهة في الماضي + نموذج تصنيف للمقارنة |
| Decision Tree | تصنيف مستوى الاستهلاك: منخفض / متوسط / مرتفع |
| Logistic Regression | تصنيف اليوم: طبيعي أو مرتفع عن المعتاد |
| SVM (RBF) | مقارنة الأداء في نفس مهام التصنيف |
| K-Means | تجميع الأيام حسب النمط (إجمالي الاستهلاك + توزيعه على أجزاء اليوم) |

### تعريف الفئات
- **المستوى (Low/Medium/High):** حدود الثلثين (terciles) محسوبة من بيانات التدريب فقط.
- **مرتفع عن المعتاد:** اليوم اللي استهلاكه أعلى من (متوسط + انحراف معياري) آخر 30 يوم قبله.
  دي فئة نادرة، فالمقارنة بتتم بـ F1 والـ Recall مش بالـ Accuracy بس.

## أسئلة للنقاش مع الطلبة
- ليه Linear Regression لازم تتقارن بخط الأساس "زي أمس"؟
- ليه الـ Accuracy مضللة في مهمة "مرتفع عن المعتاد"؟
- إيه تأثير تقسيم الداتا عشوائيًا بدل زمنيًا؟
- هل K-Means لقت أنماط حقيقية؟ (بصوا على الـ silhouette)
- إيه حدود التعميم من منزل واحد؟
